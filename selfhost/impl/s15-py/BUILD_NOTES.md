# BUILD_NOTES

## Layout
- `duramen.py`: the whole implementation (reader, checks, oracle runner, suite, judge, request handling).
- `driver.py`: the driver; `REGEN.json` names it (`python3 driver.py`, `py -3 driver.py` on Windows).
- `test_requirements.py`, `test_spec_examples.py`: tests (`unittest`).
- `spec_examples.json`: every example of SPEC.md (232), generated by `tools/extract_examples.py` (run it again after changing SPEC.md); `tools/coverage.py` lists spec examples the JSON misses.

## Build
Nothing to build: Python 3.11+, standard library only. The oracle examples need `node` on the PATH (the spec's own fixture `echo.mjs` is a Node.js program).

## Test
    python3 -m unittest            (Windows: py -3 -m unittest)

## Run
    python3 driver.py < requests.jsonl

## Notes
- The spec's examples were extracted mechanically and all pass; the hand-written tests add at least one case per requirement.
- The oracle is started in a temporary copy of the request's files (see CHOICES.md C-11).
- Surprises: request lines need ECMAScript's `JSON.stringify` key ordering (integer-like keys first) and number formatting, both reimplemented by hand; the table-header sentence about declared fields (C-7) and "states no expectation" in T024 (C-9) are the least clear parts of the spec.
